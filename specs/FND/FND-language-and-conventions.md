# 1.2 Language and conventions

<!-- Generated layout: edit text between the markers; keep the markers and the front matter. -->

> TypeScript strict mode, ESLint, Prettier, Husky, lint-staged, commitlint

<!-- section:purpose -->
## Purpose and scope

Sets the TypeScript compiler settings, lint and format rules, git hook behaviour and commit message format for every package and app. The aim is that most mistakes that matter on this platform (unhandled promises, raw SQL that bypasses tenant context, personal data in logs, hard-coded user-facing strings) are caught by a tool before review. Repo layout is in [[FND-monorepo]]; library choices are in [[APP-framework-dependencies]].

<!-- section:rules -->
## Rules

**TypeScript**
- **CONV-1** All code is TypeScript. Every `tsconfig.json` extends `@nomology/tsconfig/base.json`, which sets `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`, `isolatedModules` and `useUnknownInCatchVariables`. Packages may add settings but may not turn these off.
- **CONV-2** No `any` (explicit or implicit). Use `unknown` and narrow with Zod or type guards. `as` casts on data that crosses a trust boundary (request bodies, webhook payloads, BullMQ job data, Temporal inputs, JSON columns) are forbidden; parse with a Zod schema instead.
- **CONV-3** No floating promises; every promise is awaited, returned or explicitly handed to a supervisor (`void` is not allowed).
- **CONV-4** Errors are thrown as subclasses of `AppError` from `@nomology/api-contracts`, each mapped to a problem type in [[APP-api-error-catalogue-problem]]. Throwing strings or plain objects is forbidden.

**Data access and security**
- **CONV-5** `$queryRawUnsafe` and `$executeRawUnsafe` are forbidden everywhere. Tagged-template `$queryRaw` is allowed only inside `packages/db` and must run inside `withTenant` (see [[MT-prisma-client-extension-wraps]]).
- **CONV-6** `process.env` is read only inside `@nomology/env` ([[FND-environment-management]]).
- **CONV-7** No `console.*`; use the logger from `@nomology/observability`, which redacts fields tagged as personal data ([[OBS-foundations]]).
- **CONV-8** No `dangerouslySetInnerHTML` outside the sanitising `SafeHtml` component in `@nomology/ui`.

**Internationalisation**
- **CONV-9** No user-facing string literals in JSX or in server messages; use message IDs from `@nomology/i18n` ([[I18N-i18n#rules]]). No `toLocaleString`, `toLocaleDateString` or manual date formatting; use the formatters in [[I18N-l10n]].

**Naming**
- **CONV-10** Files and folders: `kebab-case.ts`; React components: `PascalCase` exports in `kebab-case.tsx` files; types and Zod schemas: `PascalCase` with `Schema` suffix for schemas (`CaseCreateSchema`); Prisma models `PascalCase` singular mapped to `snake_case` plural tables with `@@map`; columns `snake_case` via `@map`; the tenant column is always `tenant_id`.
- **CONV-11** Identifiers exposed in URLs or APIs are UUIDs (proposed: UUIDv7 generated by the application); sequential integers are never exposed.

**Format, hooks and commits**
- **CONV-12** Formatting is Prettier with the shared config; no formatting debates in review.
- **CONV-13** Pre-commit hook (Husky) runs lint-staged (ESLint `--fix` and Prettier on staged files) and `gitleaks protect --staged`. Commit-msg hook runs commitlint.
- **CONV-14** Commit messages and pull request titles follow Conventional Commits with a scope that names the package or app (`feat(domain-cases): add withdrawal reason`). Breaking changes use `!` and a `BREAKING CHANGE:` footer.
- **CONV-15** Every `eslint-disable` and `@ts-expect-error` carries a reason and a ticket ID (`// eslint-disable-next-line no-restricted-syntax -- PLAT-123: ...`). `@ts-ignore` is forbidden.

<!-- section:rationale -->
## Rationale

- **CONV-2** Data from parties, aggregators and webhooks is untrusted. A cast tells the compiler a lie; a Zod parse checks it at runtime and produces a typed error.
- **CONV-3** A floating promise in a Server Action or Temporal activity can fail silently after the response is sent, leaving a filing half-recorded with no audit event.
- **CONV-5** Raw SQL through `Unsafe` methods invites injection and is the easiest way to forget the tenant transaction. RLS still applies, but a query with no tenant set must fail loudly, not run under the wrong context.
- **CONV-7** `console.log` of a request body can write party names, emails or case content to log storage that has a different retention and residency profile.
- **CONV-9** Tenants need English, Hindi and other languages, and legal deadlines must show the seat time zone; hand-formatted strings defeat both.
- **CONV-11** Sequential IDs let a user guess other cases' URLs and reveal case volumes per tenant.

## Tooling and configuration

| Tool | Package / config |
|---|---|
| TypeScript (pinned 5.x; the native compiler preview is tracked but not adopted) | `tooling/tsconfig/base.json`, `nextjs.json`, `node-lib.json`, `worker.json` |
| ESLint 9 flat config | `tooling/eslint-config` exporting `base`, `react`, `next`, `node`; uses `typescript-eslint` (`strict-type-checked`), `eslint-plugin-react-hooks`, `@next/eslint-plugin-next`, `eslint-plugin-jsx-a11y`, `eslint-plugin-import-x` |
| Custom rules | `tooling/eslint-config/rules/`: `no-raw-unsafe`, `no-process-env`, `no-locale-format`, `require-ticket-on-disable` |
| Prettier 3 | `tooling/prettier-config` |
| Husky 9, lint-staged | `.husky/pre-commit`, `.husky/commit-msg`, `lint-staged.config.mjs` |
| commitlint | `commitlint.config.mjs` extending `@commitlint/config-conventional`, `scope-enum` generated from workspace package names |
| gitleaks | `.gitleaks.toml` with custom rules for our secret formats |

Sketch of the restriction block in the shared ESLint config:

```js
{
  rules: {
    '@typescript-eslint/no-floating-promises': 'error',
    '@typescript-eslint/no-explicit-any': 'error',
    'no-console': 'error',
    'no-restricted-imports': ['error', { paths: [{ name: '@prisma/client', message: 'MONO-6: use @nomology/db' }] }],
    'no-restricted-syntax': ['error',
      { selector: "MemberExpression[property.name=/^\\$(query|execute)RawUnsafe$/]", message: 'CONV-5' },
      { selector: "MemberExpression[object.name='process'][property.name='env']", message: 'CONV-6: use @nomology/env' }],
  },
}
```

Git hooks can be skipped with `--no-verify`, so every hook check is repeated in CI. A pull request that changes `tooling/eslint-config/**` or `tooling/tsconfig/**` needs CODEOWNERS approval from engineering excellence.

<!-- section:examples -->
## Examples

Good: validated webhook input and a typed error.

```ts
const payload = AggregatorStatusSchema.safeParse(await req.json());
if (!payload.success) throw new ValidationError('aggregator.status.invalid', payload.error);
```

Bad: cast and console.

```ts
const payload = (await req.json()) as AggregatorStatus; // CONV-2
console.log('received', payload);                       // CONV-7: may contain party names
```

Good: `feat(domain-documents)!: require content hash on upload` with `BREAKING CHANGE: clients must send sha256`. Bad: `fixed stuff`.

<!-- section:exceptions -->
## Exceptions

Inline suppressions need a reason and ticket (CONV-15). Package-wide deviations (for example relaxing `noUncheckedIndexedAccess` in generated code) go in the exceptions file defined in [[FND-monorepo#exceptions]]. CONV-5, CONV-6 and CONV-7 are non-waivable in production code; test code may read `process.env` through the test helpers only.

<!-- section:adoption -->
## Adoption and migration

New repo: all rules on from day one. Code migrated from the existing CORD and TERES codebases is linted with a baseline file (ESLint suppressions generated once, then only allowed to shrink); the baseline count is a tracked metric.

## Template checks

<!-- check:enforcement -->
### Enforcement

Every rule is enforced by TypeScript, ESLint, Prettier, commitlint, gitleaks or a CI script, except the problem-type mapping part of CONV-4, which is a review item. Hooks are convenience only; CI repeats all of them as required checks. The `tsconfig-guard` script and CODEOWNERS on `tooling/**` stop a pull request from quietly weakening the configuration.

<!-- check:guardrails -->
### Security, tenancy and privacy guardrails

CONV-5 and CONV-6 protect tenant isolation and secrets; CONV-7 and CONV-8 protect personal data and XSS; gitleaks on pre-commit and CI protects secrets; CONV-9 forces strings through the i18n layer so locked legal text cannot be bypassed with a literal. Accessibility lint (`jsx-a11y`) is on in the React config; full accessibility testing is in [[TST-accessibility-testing]].

<!-- check:onboarding -->
### Onboarding and usability

`pnpm lint --fix` resolves formatting and most lint findings. Each custom rule message names the rule ID and links to this node. Editor settings (`.vscode/settings.json`, recommended extensions) are committed so format-on-save and ESLint work on first open.

<!-- check:measurement -->
### Adoption measurement

Tracked: count of inline suppressions by rule (target trending down), legacy baseline size, and commitlint failure rate on PRs. Reported on the engineering health dashboard monthly.

<!-- check:ownership -->
### Ownership and change

Owner: engineering excellence lead. Config and this text change in the same pull request. Reviewed yearly and on major upgrades of TypeScript, ESLint or Next.js.
