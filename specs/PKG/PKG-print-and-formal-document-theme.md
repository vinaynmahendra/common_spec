# 5.14.1.5 Print and formal document theme

<!-- Generated layout: edit text between the markers; keep the markers and the front matter. -->

> Fixed print theme for awards, procedural orders and eBundles (A4 / US Letter), independent of viewer mode

<!-- section:purpose -->
## Purpose and scope

Defines the fixed theme used for formal legal outputs: awards, procedural orders, receipts, notices of arbitration generated by the platform, and eBundles (cover, index, separators and page stamps, see [[DOM-ebundling]]). It also defines browser print styles for any screen. The theme is the same in every viewer mode, so a document printed by a user in dark mode is identical to one printed in light mode. Accessibility of generated PDFs (tagging, PDF/UA) is specified in [[DOM-accessible-documents-and]]; this node covers visual tokens and layout only.

<!-- section:architecture -->
## Token architecture and naming

Tokens in `packages/tokens/src/print/print.tokens.json`, built to `dist/pdf/print.json` (resolved values in pt and mm) and to `dist/css/print.css` (wrapped in `@media print`). The PDF renderer in `packages/documents` reads `print.json`; it never reads mode or tenant brand tokens except the explicitly allowed slots below. Print tokens are named `print.*` (for example `print.page.margin.top`, `print.typography.body`).

<!-- section:colour -->
## Colour

| Token | Value | Note |
|---|---|---|
| `print.color.text` | #000000 | All body text |
| `print.color.text-secondary` | #3C4452 (neutral.700) | Headers, footers, page numbers; 9.8:1 on white |
| `print.color.rule` | #6B7484 (neutral.500) | Table borders, separators |
| `print.color.background` | #FFFFFF | Never a dark or tinted page background |
| `print.color.status` | none | Status is printed as text, not colour |

Tenant colours are not used in the document body. The tenant primary colour may appear only as a thin rule on the cover page, and only if it has at least 3:1 against white; otherwise the rule is black.

<!-- section:typography -->
## Typography

| Token | Value |
|---|---|
| `print.typography.body` | Source Serif 4 (or the Noto Serif family for the document language), 11 pt, line height 1.5 |
| `print.typography.heading.1` | Same family, 16 pt, bold |
| `print.typography.heading.2` | 13 pt, bold |
| `print.typography.heading.3` | 11 pt, bold |
| `print.typography.footnote` | 8.5 pt |
| `print.typography.para-number` | 11 pt, tabular figures, hanging in the margin |
| `print.typography.stamp` | Inter 8 pt, used for eBundle page stamps (`Bundle B / Tab 3 / p. 47`) |

Fonts are embedded and subset in the PDF; the document language is set so screen readers pick the right voice.

<!-- section:spacing -->
## Spacing, sizing and layout

| Token | A4 (210 × 297 mm) | US Letter (8.5 × 11 in) |
|---|---|---|
| `print.page.margin.top` | 25 mm | 1 in |
| `print.page.margin.bottom` | 25 mm | 1 in |
| `print.page.margin.inline-start` | 30 mm (binding side) | 1.25 in |
| `print.page.margin.inline-end` | 20 mm | 0.75 in |
| `print.header.height` | 12 mm | 0.5 in |
| `print.footer.height` | 12 mm | 0.5 in |

Paper size comes from the tenant setting (`document.paperSize`: `A4` default for India and Singapore tenants, `Letter` default for US tenants), and can be fixed by institutional rules. Paragraph numbering, page numbering ("Page 3 of 41") and the case reference are in the running footer on every page. Inline-start margins follow the document's writing direction.

<!-- section:shape -->
## Radius, borders and elevation

No shadows, no rounded corners, no tinted backgrounds. Tables use 0.5 pt rules.

<!-- section:iconography -->
## Iconography and imagery

No icons in formal documents except the institution's logo on the cover and the platform's AI-content marker where an AI-assisted summary is included in a non-award document (see [[AI-ai-generated-text-labelling-and]]). Awards never carry AI markers or platform branding inside the body.

<!-- section:theming -->
## Theming and tenant branding

Allowed tenant slots on formal documents, configured per institution and approved by the tenant admin:

| Slot | Where | Limits |
|---|---|---|
| Institution logo (print variant, monochrome or colour) | Cover page top, 30 mm max width | SVG or PNG at 300 dpi, sanitised |
| Institution name and address block | Cover page, letterhead | Text from tenant settings |
| Cover rule colour | Cover page | Must reach 3:1 on white, else black |
| Document templates (award structure, headings) | Body structure | Owned by [[PKG-document-and-notification]], not by this theme |

Each institution's cover template is approved by that institution before first use; the approval is recorded with the template version. Assumption: some institutions will require their own award layout; that is handled as a document template variant, not as a theme override.

<!-- section:modes -->
## Colour modes and user preferences

Independent of viewer mode. `@media print` in `dist/css/print.css` forces `color-scheme: light`, white background, black text, hides navigation and interactive controls, expands collapsed sections, prints link URLs after link text for external links, and avoids page breaks inside table rows and headings.

<!-- section:distribution -->
## Build, distribution and consumption

`dist/pdf/print.json` is consumed by the PDF renderer worker (BullMQ job or Temporal activity in the document generation pipeline, [[WF-long-running-pipelines]]). The renderer records the token package version and template version in the PDF metadata and in the document version row ([[DOM-documents-schema]]), so the exact appearance of an issued award can be reproduced.

<!-- section:governance -->
## Governance, versioning and deprecation

Any change to print tokens is a major release, because it changes the appearance of formal records. It needs sign-off from the design system owner and product, and a notice to institution tenants in release notes. Already issued documents are never re-rendered; they are stored as issued.

<!-- checks -->
## Template checks

<!-- check:accessibility -->
### Accessibility by construction

Print text is black on white (21:1); secondary text is 9.8:1. Status is printed as words. Tagging, reading order and bookmarks for PDF/UA are owned by [[DOM-accessible-documents-and]].

<!-- check:tenancy -->
### Tenant theme isolation and safety

Only the approved cover slots are tenant-specific; they are read from the tenant's own settings within the tenant transaction when the document is rendered.

<!-- check:change-safety -->
### Change safety and blast radius

Print token changes are major releases with tenant notice; issued documents are never re-rendered and record the token and template versions used.

<!-- check:surfaces -->
### Coverage across surfaces and formal outputs

This theme is the only source for formal outputs: PDF renderer and browser print. It ignores dark mode and tenant marketing colours; tenant influence is limited to the cover logo, name block and a cover rule colour that must reach 3:1. Page size A4 or US Letter by tenant setting, with fixed margins.
